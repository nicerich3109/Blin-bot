# Discord-бот: заявки на вступление и отпуск

## Файлы
- `config.py` — все ID каналов/категорий/ролей и токен.
- `bot.py` — вся логика бота.
- `requirements.txt` — зависимости.
- `data.json` — создаётся автоматически при первом запуске, хранит
  заявки, отпуска, счётчики номеров и ID персистентных сообщений.
  **Не удаляйте его без необходимости** — при удалении собьётся
  нумерация заявок и потеряется история.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. В Discord Developer Portal у приложения бота включите
   **Privileged Gateway Intents → Server Members Intent**.
2. Выдайте боту на сервере права: `Manage Roles`, `Manage Channels`,
   `Manage Nicknames`, `View Channels`, `Send Messages`,
   `Embed Links`, `Read Message History`.
3. **Важно:** роль бота в списке ролей сервера должна быть **выше**
   ролей `Recrut Blin`, `Chief Recrut Blin`, ролей новых участников и
   ролей отпуска — иначе бот не сможет их выдавать/снимать и менять
   ники людям с этими ролями.
4. Задайте токен бота через переменную окружения:
   ```bash
   export DISCORD_TOKEN="ваш_токен"
   ```
   либо впишите его прямо в `config.py` (не рекомендуется, если
   код где-то публикуется).
5. При необходимости откройте `config.py` и поправьте
   `GUILD_ID` (ID вашего сервера) — тогда слэш-команды
   (`/принял`, `/отклонил`) появятся на сервере мгновенно после
   запуска. Если оставить `None`, Discord обновит команды глобально
   (может занять до часа).
6. Проверьте, что все ID в `config.py` совпадают с реальными ID
   каналов/категорий/ролей на вашем сервере (Настройки → Дополнительно →
   Режим разработчика, затем ПКМ → «Копировать ID»).

## Запуск

```bash
python3 bot.py
```

При старте бот:
- сам разместит (или обновит, если уже есть) сообщение с кнопкой
  «Подать заявку» в канале заявок на вступление;
- сам разместит (или обновит) сообщения с кнопкой и списком
  отпускников в обоих каналах отпусков (DN и PHX).

## Как это работает

### Заявки на вступление
1. Пользователь жмёт «Подать заявку» → открывается модалка (шаг 1/2):
   никнейм, статик, OOC возраст, планы, откуда узнали (5 полей —
   максимум для одной модалки Discord).
2. После отправки сразу открывается модалка (шаг 2/2) с полем
   «Сервер» (DN/PHX).
3. Создаётся приватный канал `DN-001` / `PHX-001` (нумерация раздельная
   для DN и PHX) в соответствующей категории, с доступом только
   заявителю и рекрутёрам/чиф-рекрутёрам этого сервера. Они пингуются.
4. Рекрутёр пишет `/принял номер:DN-001` или
   `/отклонил номер:DN-001 причина:...` (номер подсказывается
   автодополнением). У полей есть проверка прав — команду может
   выполнить только рекрутёр/чиф-рекрутёр нужного сервера или админ.
5. Результат уходит в канал логов заявок (DN/PHX) со всеми данными
   анкеты. При одобрении заявителю меняется ник на
   `New Blin DN/PHX Имя` (первое слово из поля «никнейм») и выдаётся
   роль нового участника. Тикет-канал не удаляется, а закрывается на
   отправку сообщений заявителем (история остаётся видна).

### Отпуска
1. В канале отпуска (свой для DN и свой для PHX) пользователь жмёт
   «Подать заявку» → одна модалка на 4 поля: ID дискорда (можно
   вставить упоминание `@ник` или просто ID), дата окончания (формат
   `31.10.26`), причина, сервер.
2. Отдельный канал не создаётся — заявка сразу уходит в канал логов
   (DN/PHX) в виде сообщения с данными и кнопками «Принять»/«Отклонить».
3. При принятии указанному в «ID дискорда» человеку выдаётся роль
   отпуска соответствующего сервера, а в канале отпуска обновляется
   список «сейчас в отпуске».
4. Раз в час (настраивается в `config.py`,
   `VACATION_CHECK_INTERVAL_MINUTES`) фоновая задача проверяет даты
   окончания и автоматически снимает роль в день, когда отпуск
   заканчивается, обновляя список.

## Принятые допущения (там, где в ТЗ было неоднозначно)

- В исходном ТЗ поле «Сервер» есть и в заявке на вступление (общий
  канал для обоих серверов), и в заявке на отпуск (хотя там уже есть
  отдельный канал под каждый сервер). Реализовано буквально — поле
  «Сервер» есть в обеих формах как текстовое поле с подсказкой
  `DN/PHX`, как и остальные поля.
- Заявка на вступление разбита на 2 модалки подряд, так как Discord
  не позволяет больше 5 полей в одной модалке, а полей в ТЗ шесть
  (никнейм, статик, возраст, планы, источник, сервер).
- Кто может принимать/отклонять заявки на отпуск — в ТЗ явно не
  указана роль (упомянут только абстрактный «high staff»). По
  умолчанию используются те же роли рекрутёров/чиф-рекрутёров
  (`config.VACATION_STAFF_ROLE_IDS`) — список легко расширить, добавив
  туда ID вашей роли High Staff.
- При отклонении/одобрении заявки на вступление тикет-канал не
  удаляется автоматически (чтобы не терять историю переписки), а
  просто лишается права заявителя писать в него. При желании можно
  добавить автоудаление через `channel.delete()` — отметил место в
  коде (`process_join_decision`, блок «Тикет-канал»).
- Дата отпуска парсится в форматах `31.10.26` и `31.10.2026`.
