# Discord-бот Blin — заявки на вступление и отпуск

## Структура проекта

| Файл | Назначение |
|---|---|
| `config.py` | Все ID каналов/разделов/ролей и токен. |
| `logger_setup.py` | Настройка логирования в консоль и в файл `bot.log`. |
| `storage.py` | Хранение данных в `data.json` (заявки, отпуска, счётчики). |
| `utils.py` | Общие функции: парсинг даты/времени, права доступа, безопасный поиск участника, персистентные сообщения. |
| `decisions.py` | Общая логика принятия/отклонения заявок (и для вступления, и для отпуска). |
| `ui_decision.py` | Кнопки «Принять»/«Отклонить» и модалка причины отказа. |
| `applications.py` | Заявки на вступление: кнопки Denver/Phoenix, модалка, создание тикет-канала. |
| `vacations.py` | Заявки на отпуск: модалка, список отпускников, снятие роли по сроку. |
| `commands.py` | Слэш-команды `/принять` и `/отклонить`. |
| `bot.py` | Точка входа — запускать нужно именно этот файл. |

## Установка

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. В Discord Developer Portal у приложения бота включите **Privileged
   Gateway Intents → Server Members Intent**.
2. Выдайте боту права: `Manage Roles`, `Manage Channels`,
   `Manage Nicknames`, `View Channels`, `Send Messages`,
   `Embed Links`, `Read Message History`.
3. **Важно:** роль бота должна стоять **выше** ролей рекрутёров,
   новых участников и ролей отпуска в списке ролей сервера — иначе
   бот не сможет их выдавать/снимать и менять ники таким людям.
4. Задайте токен бота:
   ```bash
   export DISCORD_TOKEN="ваш_токен"
   ```
5. При необходимости укажите `GUILD_ID` в `config.py` — тогда
   слэш-команды появятся на сервере мгновенно после запуска (иначе
   обновление может занять до часа).
6. Проверьте, что все ID в `config.py` совпадают с реальными ID на
   вашем сервере (Настройки → Дополнительно → Режим разработчика →
   ПКМ по каналу/роли → «Копировать ID»).

## Запуск

```bash
python3 bot.py
```

Логи пишутся одновременно в консоль и в файл `bot.log` (с ротацией —
старые логи архивируются, файл не растёт бесконечно). При проблемах с
выдачей ролей или другими действиями бота в первую очередь смотрите
именно `bot.log` — там указана точная причина (участник не найден,
роль не найдена, у бота нет прав и т.п.).

При старте бот сам разместит (или обновит, если уже есть) сообщения с
кнопками в канале заявок на вступление и в обоих каналах отпуска
(Denver и Phoenix).

## Как это работает

### Заявки на вступление
1. В канале заявок пользователь видит текст и две кнопки: **Denver**
   (синяя) и **Phoenix** (красная).
2. Нажатие открывает модалку из 3 полей: никнейм, статик, OOC возраст.
3. Создаётся приватный тикет-канал `DN-001` / `PHX-001` (нумерация
   раздельная) в нужном разделе, с доступом заявителю и
   рекрутёрам/чиф-рекрутёрам этого сервера. Прямо в тикете сразу висят
   кнопки **Принять** / **Отклонить**.
4. Обработать заявку можно либо этими кнопками, либо командой
   `/принять номер` / `/отклонить номер причина` (номер подсказывается
   автодополнением). Отказ через кнопку открывает модалку с причиной.
5. Результат уходит в канал логов заявок. При одобрении заявителю
   меняется ник на `New Blin DN/PHX Имя` (первое слово из «никнейма») и
   выдаётся роль нового участника. Тикет-канал не удаляется, но
   заявитель теряет право писать в него.

### Заявки на отпуск
1. В своём канале (отдельно для Denver и Phoenix) пользователь жмёт
   «Подать заявку» → модалка из 4 полей: ID дискорда, дата окончания
   (`31.10.26`), время окончания с шагом в полчаса (`10:00` / `10:30`),
   причина. Сервер определяется каналом, поэтому отдельного поля для
   него нет.
2. Заявка сразу уходит в канал логов соответствующего сервера с
   кнопками **Принять** / **Отклонить** (отказ — с модалкой причины),
   так же можно обработать командами `/принять` / `/отклонить`.
3. При одобрении указанному участнику выдаётся роль отпуска, в канале
   отпуска обновляется список «сейчас в отпуске» с точным временем
   окончания.
4. Раз в `config.VACATION_CHECK_INTERVAL_MINUTES` минут (по умолчанию
   15) бот проверяет, не истёк ли срок, и автоматически снимает роль,
   обновляя список.

## Допущения по неоднозначным местам ТЗ

- Поле «время окончания отпуска» трактуется как точное время суток на
  дату окончания (то есть дата + время = точный момент, когда роль
  будет снята), а не как общая продолжительность отпуска в часах.
- Право принимать решения по заявкам на отпуск дано тем же
  рекрутёрам/чиф-рекрутёрам, что и по заявкам на вступление
  (`config.VACATION_STAFF_ROLES`) — в ТЗ конкретная роль не была
  указана. Список легко расширить нужной ролью.
- Интервал фоновой проверки отпусков увеличен с предложенных 10 до 15
  минут — обоснование см. в комментарии рядом с
  `VACATION_CHECK_INTERVAL_MINUTES` в `config.py`.

## История изменений

### v1.0
- Заявки на вступление: кнопка «Подать заявку» → 2 модалки (никнейм,
  статик, возраст, планы, источник + отдельно сервер текстом) →
  создание тикет-канала → обработка командами `/принял`/`/отклонил`.
- Заявки на отпуск: кнопка → модалка (ID дискорда, дата, причина,
  сервер текстом) → сообщение с кнопками Принять/Отклонить в логах →
  выдача роли отпуска → автоснятие роли по дате (проверка раз в час).
- Весь код в одном файле `bot.py`.

### v1.1
**Добавлено**
- Выбор сервера в заявке на вступление через отдельные кнопки
  **Denver** (синяя) / **Phoenix** (красная) вместо текстового поля.
- Кнопки **Принять** / **Отклонить** прямо в заявках (и на вступление,
  и на отпуск), в дополнение к командам.
- Модальное окно «Причина» при отказе — как для заявок на вступление,
  так и для заявок на отпуск.
- Команды `/принять` и `/отклонить` теперь работают с обоими типами
  заявок — тип определяется автоматически по номеру.
- Поле «Время окончания» в заявке на отпуск (шаг 30 минут), для более
  точного снятия роли.
- Файл `bot.log` с подробным логированием всех ключевых действий и ошибок.
- Код разложен по отдельным файлам вместо одного `bot.py`.

**Исправлено**
- Баг: роль отпуска не выдавалась при одобрении заявки. Причина —
  поиск участника только в локальном кэше гильдии, без запроса через
  API при промахе кэша. Теперь используется безопасный поиск с
  фолбэком на `fetch_member`, а любые сбои (участник не найден, нет
  прав на выдачу роли, роль не найдена в конфиге) логируются и сразу
  показываются сотруднику, обработавшему заявку.

**Убрано**
- Поля «Планы после вступления» и «Откуда узнали о нас» из заявки на
  вступление.
- Поле «Сервер» из заявки на отпуск (теперь определяется каналом, в
  котором подана заявка).
- Команды `/принял` и `/отклонил` переименованы в `/принять` и
  `/отклонить`.
